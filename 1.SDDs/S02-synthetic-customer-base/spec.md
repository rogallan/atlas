# Spec — S02 · Synthetic Customer Base

> **Domain:** Data · **Quarter:** Q1 · **Depends on:** S01 (Python Toolchain)

## 1. Goal

Model and generate a fully synthetic customer/financial-history dataset that the MCP servers and
RAG pipeline can query later, without ever touching real customer data — per the Constitution's
"100% synthetic data" principle.

## 2. Context

Several later phases (S08–S13, MCP servers) need a realistic-looking but entirely fictitious
dataset to query against. This phase defines the schema and generates that dataset once, so it can
be reused consistently across the whole project.

## 3. In scope

- Entity modeling: Customer, Account, Product, Contract, FinancialEvent, History.
- A deterministic seed and a versioned, reproducible synthetic dataset.
- Schema and data-consistency tests.
- Explicit documentation that no real data is used anywhere in the project.

## 4. Out of scope

- Any integration with real banking systems or real customer records.
- The MCP servers that will query this data (covered in S08–S13).

## 5. Requirements

- **R1.** Entities: Customer, Account, Product, Contract, FinancialEvent, History, each with a
  documented schema.
- **R2.** Data generation must be deterministic (fixed seed) so the dataset is reproducible.
- **R3.** The generated dataset is versioned in the repository (or reproducibly regenerated by a
  script — no hand-edited data files).
- **R4.** Schema tests validate structural consistency (types, required fields, referential
  integrity between entities).
- **R5.** A clearly visible disclaimer states that all data is synthetic and fictitious.

## 6. Acceptance criteria

- Running the generation script twice with the same seed produces byte-identical output.
- Schema tests pass for the generated dataset.
- No entity, name, or record in the dataset matches — or is derived from — real individuals or
  institutions.
